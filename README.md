# 就職・インターン応募用ポートフォリオの作り方

このフォルダーは、HTML・CSS を編集しながら、自分のポートフォリオを作るための教材です。完成したコードを同梱しているので、最初からすべてを書き写す必要はありません。まず動く状態を見て、文章、画像、リンクの順に自分の内容へ置き換えましょう。

氏名・所属・連絡先など、ご自身で入力した内容を反映しています。**「追記予定」「入力」と書かれた欄は未完成です。** 就職作品の仮題は「1vs1対戦におけるマッチングサービスの技術デモ」です。掲載した図は作品テーマの概念図で、実際のシステム構成を示すものではありません。インターネットへの公開はまだ行っていません。

現在は、ホームで就職作品1件を大きな画像で紹介し、PROJECT 01 の詳細ページでは画像と短い説明を並べる構成です。過去のチーム制作へのリンクは、各ページの最下部に控えめに配置しています。PC向けの表示を使用しています。

## 0. 準備するもの

- パソコンとブラウザー（Edge、Chrome など）
- コードを編集できるテキストエディター
- 自分の作品の画像、説明文、公開してよいリンク
- 公開するときに使う GitHub アカウント（ローカルで試す段階では不要）

この教材では Node.js、パッケージのインストール、ターミナルの操作は必要ありません。HTML ファイルをブラウザーで開いて確認できます。

ZIP を入手した場合は、右クリックなどで**先に展開**してください。ZIP 内のファイルをそのまま開くと、CSS や画像を正しく読み込めないことがあります。

## 1. 最初に、載せる情報を整理する

見た目を変更する前に、次の内容をメモします。作品が少ない場合は、まず1件を具体的に説明するところから始めて構いません。

| 情報 | 用意する内容 |
| --- | --- |
| 基本情報 | 氏名、公開する所属・学年、志望領域 |
| 冒頭の紹介 | 何を学び、どんなものを作っている人かを1〜2文で |
| 代表作品 | 応募先に最も見てほしい作品1件 |
| 作品の根拠 | スクリーンショット、動作動画、ソースコード、実行ページなど |
| 制作条件 | 期間、人数、自分の担当、使用技術 |
| 制作の説明 | 課題、実装、検証、改善 |
| スキル | 使用した技術と、その技術で実際にできること |
| 連絡先 | 応募先に伝えてよいメールアドレスやプロフィールの URL |

授業課題、個人制作、研究、チーム制作も掲載候補です。チームの成果は、自分の担当範囲が分かるように書きます。利用者数や改善率など、測定していない数字を実績として追加する必要はありません。

## 2. フォルダーの中身を知る

```text
portfolio-starter/
├─ index.html       トップページ
├─ project.html     就職作品の詳細ページ（PROJECT 01）
├─ team.html        過去のチーム制作ページ
├─ style.css        PC向けの色・文字・余白・配置
├─ images/
│  ├─ matchmaking-wide.svg        就職作品の横長の概念図
│  ├─ demo-screen-placeholder.svg 動作画面の仮画像
│  ├─ server-log-placeholder.svg  実行ログの仮画像
│  ├─ architecture-placeholder.svg 構成図の仮画像
│  └─ tools/                     言語・ツールのロゴとライセンス
├─ .nojekyll        GitHub Pages の公開時に使う空ファイル
└─ README.md        この説明書
```

まずはこの配置を保ってください。HTML、CSS を別々の場所へ移動すると、ファイルを読み込むためのパスの変更が必要になります。

`.nojekyll` は中身が空でも正常です。GitHub Pages で不要な Jekyll の処理を避けるためのファイルです。[GitHub の静的ファイル公開の説明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## 3. ブラウザーで開き、編集の流れを試す

1. 展開したフォルダーの `index.html` をブラウザーで開きます。ダブルクリックで開かない場合は、右クリックの「プログラムから開く」などでブラウザーを選びます。
2. 作品の詳細リンクを押し、`project.html` へ進めることを確認します。
3. テキストエディターで `index.html` を開き、仮の氏名を自分の氏名に変更します。
4. `Ctrl + S` などで保存します。
5. ブラウザーへ戻り、再読み込みします。

**「編集 → 保存 → 再読み込み」**が基本の作業です。ブラウザーに表示されているページを直接編集するのではなく、元のファイルを編集します。

Windows で新しいファイルを作成するときは、拡張子を確認してください。`index.html.txt` は HTML ファイルとは別物です。文字コードは UTF-8 で保存します。HTML ファイルをブラウザーで開く方法と基本構造は [MDN の HTML 入門](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Your_first_website/Creating_the_content)でも確認できます。

### 実際に氏名と希望職種を書き換える操作

1. このフォルダーをエクスプローラーで開きます。
2. index.html を右クリックし、「プログラムから開く」からメモ帳などのテキストエディターを選びます。ダブルクリックは通常、表示確認用のブラウザーを開きます。
3. エディターで Ctrl + F を押し、hero-name を検索します。検索欄を閉じ、見つかった行を編集します。

変更前：

```html
<p class="hero-name">あなたの名前 <span>／ 希望職種をここに</span></p>
```

変更例（氏名・希望職種は自分のものにしてください）：

```html
<p class="hero-name">山田 太郎 <span>／ ゲームプログラマー志望</span></p>
```

4. 次の行の hero-description は、名前の下に出る自己紹介文です。文章部分を自分の紹介に変更します。br は改行の目印です。
5. Ctrl + S で上書き保存します。文字コードは UTF-8 のままにします。
6. ブラウザーで同じ場所の index.html を開き、Ctrl + R または再読み込みボタンで更新します。

タグや class はそのまま残して、まず日本語の文章だけを変更しましょう。編集を間違えたら Ctrl + Z で戻せます。反映されない場合は、保存したファイルとブラウザーが開いているファイルの場所が一致しているか確認します。

ページ内の名前は、冒頭・自己紹介・ヘッダー・フッターなどに別々に記載されています。最初は冒頭の1か所だけ変更して動きを確かめ、次に「あなたの名前」「YOUR NAME」を検索して残りを置き換えます。project.html にも共通の氏名表記があるため、最後に合わせます。

## 4. HTML・CSS の役割

| ファイル | 役割 | 最初に変更すること |
| --- | --- | --- |
| HTML | 文章、見出し、画像、リンクなどの内容と構造 | 名前、紹介文、作品の説明 |
| CSS | 色、文字サイズ、余白、並び方 | 好きな色と、読みやすい見た目 |

HTML の最小の例です。

```html
<h1>山田 太郎</h1>
<p>ゲーム制作を学び、操作しやすい UI の実装に取り組んでいます。</p>
```

`h1` はページの主見出し、`p` は段落です。文章の前後にあるタグを残し、その間の内容を変えます。これは書き方の例なので、名前や紹介は自分の内容にしてください。

CSS は、対象を指定して見た目を設定します。

```css
/* h1 という要素の文字色を変更する例 */
h1 {
  color: #165a4a;
}
```

まず `style.css` の既存の色指定を探し、1か所ずつ変更して確認しましょう。同じ対象の指定を何度も追記すると、どの指定が効いているか分かりにくくなります。

この版はPC向けです。ナビゲーションは常に表示し、JavaScriptは使用していません。画面幅1100px以上を想定し、それより狭いウィンドウでは横スクロールになります。

### このコードを読むための2つのポイント

**1. HTML の `class` は見た目の目印、`id` はページ内の行き先です。**

```html
<a href="#works">作品へ移動</a>
<section class="section wrap" id="works">
  <h2>制作した作品</h2>
</section>
```

`href="#works"` のリンクを押すと、`id="works"` の場所へ移動します。`class="section wrap"` は、CSS の `.section` と `.wrap` の両方を適用するという意味です。この例は仕組みの説明なので、同じ `id` を持つ項目を追加しないでください。

**2. CSS の変数に、サイト共通の色をまとめています。**

```css
:root {
  --accent: #22654e;      /* 主な緑色 */
  --accent-dark: #194b3a; /* ボタンにマウスを重ねた色 */
}
```

実際の `style.css` の冒頭にある同じ指定を書き換えます。`var(--accent)` を使っている見出しやボタンに反映されます。背景と文字が読める組み合わせにしましょう。

## 5. 自分の内容に置き換える

### トップページ：`index.html`

次の順序で置き換えると整理しやすくなります。

1. ブラウザーのタブに出る `<title>` と、ページ説明の `<meta name="description">`
2. ページ内の氏名、所属、志望領域、冒頭の紹介文
3. 代表作品のタイトル、概要、制作条件
4. 就職作品の詳細リンクと、過去のチーム制作ページへのリンク
5. スキル、自己紹介、連絡先

タブ名とページ説明は、例えば次のように変更します。

```html
<title>山田 太郎 | ポートフォリオ</title>
<meta name="description" content="山田太郎の制作ポートフォリオ。ゲーム制作や UI 実装への取り組みを紹介します。">
```

実際のページにある該当行を編集し、同じ `<title>` を追加でもう一つ作らないようにしてください。

### 作品詳細ページ：`project.html`

既存の PROJECT 01 を、就職作品の詳細ページとして使用しています。全体像、動作画面・実行ログ、システム構成図を画像中心に掲載します。各画像の下の figcaption に短い説明を記載してください。制作期間・人数・担当・採用技術はページ下部の「制作情報と補足」にまとめ、制作目的・実装の工夫・検証結果は折りたたみ欄に記載します。学習中の技術と、作品で実際に採用した技術は区別してください。

### 過去のチーム制作ページ：`team.html`

以前トップページにあったチーム制作の欄を、このページへ移しました。作品名、期間、チーム構成、自分の担当、工夫、検証・改善を編集します。作品を追加する場合は、`<article class="work-row">` から対応する `</article>` までを複製し、番号と内容を変更します。ホームにはチーム作品のカードを置かず、各ページ最下部の「過去のチーム制作」リンクから、このページへ移動できます。

未入力の動画・GitHub・連絡先などは、誤って外部へ誘導しないよう、ひな形では実リンクを設定していません。公開先が用意できた項目にだけ、次の例でリンクを追加します。

### HTML を編集するときの小さなルール

- `href="..."` や `src="..."` の引用符を消さない。
- `<section>` を消す場合は、その区間の閉じタグ `</section>` まで対応を確認する。
- メニューが参照する `id` や、見た目に使われる `class` は、最初はそのまま使う。
- 一度に大量の変更をせず、1項目を編集したら表示を確認する。

## 6. 作品画像を差し替える

1. 自分の作品画面を撮影・保存します。
2. `work-01.jpg` など、英数字とハイフンを使った分かりやすい名前にします。
3. `images/` に入れます。
4. HTML 内で `matchmaking-wide.svg` を検索し、その画像のパスと説明を差し替えます。現在はトップページと就職作品の詳細ページで、この概念図を表示しています。

```html
<img
  src="./images/work-01.jpg"
  alt="制作したゲームのプレイ画面。画面下部に体力と操作ガイドを表示している"
>
```

このコードは書き方の例です。既存の画像タグに `class`、`width`、`height` などがある場合は、レイアウトとの関係を確認しながら編集してください。`alt` には、画像が何を伝えるのかを短く書きます。

`.jpg`、`.png`、`.webp` など、**実際の拡張子と HTML の指定を一致**させてください。ファイル名が `Work-01.jpg` なら、大文字・小文字も合わせます。トップページと詳細ページの両方に仮画像がある場合は、両方を差し替えます。

### 動作画面とログを差し替える場所

詳細ページの画像は、次の対応で差し替えます。現在は実際の画面が未提供のため、「画像を追加予定」と表示しています。

| HTMLで検索するファイル名 | 差し替える内容 |
| --- | --- |
| demo-screen-placeholder.svg | 実際の動作確認画面 |
| server-log-placeholder.svg | 実際のサーバーの実行ログ |
| architecture-placeholder.svg | 実際に採用したシステム構成図 |

例えば images/demo-screen.png を保存したら、project.html の該当画像を次のように変更します。

```html
<img src="./images/demo-screen.png" alt="ここに実際の画面が示している内容を書く">
```

画像のすぐ下の figcaption も「何をしている場面か」「何が確認できるか」の1〜2文に置き換えます。画像は縦横比を維持して全体を表示します。実際のログに認証情報などが含まれる場合は、掲載前に該当箇所を隠してください。

### 使用言語・ツール欄の編集

index.html の tool-grid 内に、AWS・C言語・Go・MySQL・Git・GitHub・SourceTree・DirectX 11・C++・Visual Studio 2022の10項目を配置しています。AWS・Go・MySQLは、自己紹介にある学習状況を反映しています。C言語は「授業・制作で使用」、追加された6項目は「使用経験あり」と記載しています。具体的な担当機能や制作物については、実際の経験に合わせて追記してください。DirectX 11には、このサイト用の文字アイコンを使用しています。

各項目の tool-state を「学習中」「授業で使用」「作品で使用」など実際の経験に合わせて変更し、最後の p に具体的な利用例を記載してください。先輩のサイトにある技術を、自分の使用実績として一括で追加する必要はありません。AWSの個別サービス名は実際に使用したものを記載します。

ロゴは images/tools/ に同梱しており、オフラインでも表示できます。入手元とライセンスは THIRD_PARTY_NOTICES.md に記載しています。

## 7. 動画・GitHub・メールへのリンクを追加する

以下の URL やメールアドレスは例です。**そのまま掲載せず、自分の有効な公開先に置き換えてください。** 未入力の説明文が置かれている位置を、必要なリンクへ変更します。

### YouTube の動画

まずは、埋め込みプレーヤーより設定の少ない外部リンクで十分です。

```html
<a href="https://www.youtube.com/watch?v=YOUR_VIDEO_ID">
  作品の動作動画を見る（YouTube）
</a>
```

YouTube の「共有」から得た URL を、`href` の中に貼り付けます。動画の概要欄に、操作方法や見どころを書いておくと説明を補えます。

### GitHub のソースコード

```html
<a href="https://github.com/YOUR_NAME/YOUR_REPOSITORY">
  ソースコードを見る（GitHub）
</a>
```

応募先がアクセスできる公開範囲か確認してください。チーム制作の場合は、リポジトリだけでなく、このページにも自分の担当を明記します。

### メール

```html
<a href="mailto:career@example.com">
  career@example.com
</a>
```

`mailto:` は閲覧者のメールアプリを開くリンクです。Web サイト自体に問い合わせフォームを設置したり、メールを自動送信したりする機能ではありません。公開するアドレスに変更してください。

### 別タブで開きたい場合

通常のリンクは同じタブで開きます。別タブにするなら、次の属性を追加します。

```html
<a
  href="https://github.com/YOUR_NAME/YOUR_REPOSITORY"
  target="_blank"
  rel="noopener noreferrer"
>
  ソースコードを見る（別タブ）
</a>
```

## 8. 採用担当者に伝わる作品説明を書く

作品について、「何を作ったか」と「自分がどのように考えて作ったか」が読める状態を目指します。

```text
作品名：
何を作ったか：
制作期間：
制作人数：
自分の担当：
使用技術：

課題：誰が、どんな場面で、何に困っていたか。
実装：その課題に対して、何を、なぜその方法で実装したか。
検証：何を確認したか。どう確認し、どの結果が得られたか。
改善：残っている問題と、次に取り組むこと。
```

たとえば「UI を工夫した」だけでは、作業の内容が伝わりにくくなります。「操作ガイドを初回表示に追加し、初めて遊ぶ人が開始操作を見つけられるか確認した」のように、変更と確認方法を具体化します。これは文章の型の例であり、実際に行ったことだけを書いてください。

未検証のものは「今後、初見の利用者に操作してもらい確認予定」と書けます。チーム作品では「企画・全体開発はチーム、私はメニュー UI と入力処理を担当」のように範囲を分けます。

スキルにも根拠を添えます。例えば「HTML・CSS：作品紹介ページの文章と配置を調整」のような説明です。この教材を使っただけで、内容を理解・実装した実績として扱う必要はありません。自分で変更し、説明できるようになった範囲を書きましょう。

## 9. 公開前にローカルで確認する

- すべての仮の氏名、作品、文章、画像を確認したか。
- トップページと作品詳細を行き来できるか。
- メニューや折りたたみ項目が操作できるか。
- PCのブラウザー（幅1100px以上）で、文字や画像の配置が読みやすいか。
- 画像が表示され、内容に合う説明文になっているか。
- 動画、GitHub、メールのリンク先が正しいか。
- 制作期間・人数・担当・使用技術が実際の内容と一致しているか。

各ページを書き終えたら、その HTML の冒頭にある `<div class="template-note">…</div>` を削除できます。画像下の案内や、詳細ページの「追記する内容」も、実際の作品に合った文章へ直してください。

リンク先は、ログインしていない閲覧者も見られる状態か確認します。YouTube や GitHub など、外部サービスの公開設定は、この HTML の編集とは別に行います。

## 10. GitHub Pages で公開する

ここからは、完成したファイルを自分で公開する手順です。GitHub Free で使う場合は、公開用リポジトリを Public にします。[GitHub Pages の公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

### 10-1. リポジトリを作る

1. GitHub にログインします。
2. `New repository` を選びます。
3. 名前を `portfolio` にします。リポジトリは、ファイルを保存するための入れ物です。
4. 公開範囲を `Public` にします。
5. `Add README` を有効にして作成します。これで `main` ブランチを用意できます。

### 10-2. ファイルをアップロードする

1. リポジトリを開き、`Add file` → `Upload files` を選びます。
2. `index.html`、`project.html`、`team.html`、`style.css`、`images/`、`.nojekyll` をアップロードします。この教材の `README.md` は公開に必須ではありません。
3. 変更内容に `Add portfolio website` などと入力して、変更を保存（コミット）します。

**`portfolio-starter` フォルダーごとを一段深く置かず、その中身をリポジトリ直下に配置してください。** リポジトリを開いたとき、すぐに `index.html` が見える状態が正解です。画像フォルダーは、そのまま `images/` として配置します。

新しいブランチに変更を提案した場合は、Pull Request を作成・マージし、`main` に反映します。画面に表示される保存ボタン名は、選んだ保存方法によって変わります。[GitHub のファイル追加手順](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)

### 10-3. 公開設定をする

1. リポジトリの `Settings` を開きます。
2. 左側の `Pages` を選びます。
3. `Build and deployment` の `Source` で `Deploy from a branch` を選びます。
4. `Branch` を `main`、フォルダーを `/(root)` にして、`Save` を押します。
5. 公開処理が終わったら、同じ画面の `Visit site` から開きます。

名前を `portfolio` にした場合、公開 URL は通常、次の形式です。

```text
https://あなたのGitHubユーザー名.github.io/portfolio/
```

公開元は [GitHub の公式設定手順](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)を確認できます。反映に最大10分程度かかる場合があります。[GitHub Pages のクイックスタート](https://docs.github.com/en/pages/quickstart)

### 10-4. 公開したページを確認・更新する

公開 URL をPCのブラウザーで開き、画像、文字、メニュー、動画リンクを確認します。確認が終わった URL を応募書類などに記載します。

更新は、ローカルのファイルを修正して確認し、変更したファイルを同じ場所にアップロードしてコミットします。`main` の公開元へ反映されると、サイトも更新されます。

## 11. よくあるつまずき

| 症状 | 確認すること |
| --- | --- |
| 文字だけで、デザインが付かない | `style.css` が HTML と同じフォルダーにあるか。読み込み先のファイル名が一致しているか |
| 画像が表示されない | `images/` の配置、ファイル名、拡張子、大文字・小文字が一致しているか |
| 編集した内容が反映されない | 編集したファイルを保存したか。別の場所にあるコピーを開いていないか。ブラウザーを再読み込みしたか |
| 文字が化ける | UTF-8 で保存しているか。HTML の `meta charset` を消していないか |
| HTML が文字として表示される | ファイル名が `.html.txt` になっていないか |
| 公開 URL が 404 になる | Pages の公開元が `main` / `/(root)` か。その直下に `index.html` があるか。公開処理が完了したか |
| ローカルでは動くのに、公開後は画像が消える | `C:\...` のような自分の PC のパスを使っていないか。大文字・小文字が一致しているか |
| 公開後だけ CSS・画像が読み込めない | `/style.css` のようなドメイン直下への指定ではなく、`./style.css`、`./images/work-01.jpg` のように相対パスを使っているか |

GitHub Pages の 404 は、[公式の確認項目](https://docs.github.com/en/pages/getting-started-with-github-pages/troubleshooting-404-errors-for-github-pages-sites)も参照できます。公開に失敗した場合は、リポジトリの `Actions` に表示される公開処理の結果を確認します。

## 就職作品に「画像＋詳細説明」を追加・編集する

`project.html` の「機能・処理ごとの詳細」に、受付・待機・成立・ログ・データ管理・実行環境の6欄を用意しています。見出しも説明も仮の内容なので、実際の作品に合わせて変更してください。実装していない項目は削除できます。

画像は左、説明は右に表示します。PCの通常幅では画像の枠は約580px×310pxです。画像全体が収まるように表示するため、縦横比によって余白ができます。画像をクリックすると新しいタブで大きく確認できます。ページ上部の目次から各項目へ移動できます。

### 1. 画像と文章を差し替える

1. スクリーンショットを `images/` に保存します。例：`matching-wait.png`。
2. `project.html` をメモ帳などで開き、Ctrl+Fで `id="waiting"` を検索します。
3. その欄の `href="./images/matching-wait-placeholder.svg"` と `src="./images/matching-wait-placeholder.svg"` を、**両方とも** `./images/matching-wait.png` に変更します。`href` はクリック先、`src` はページに表示する画像です。
4. `alt` は画像の内容を表す文章にします。例：`プレイヤーAが対戦相手を待っている画面。`。
5. `<h3>` の見出し、`<p>` の概要、`<dt>` の小見出し、`<dd>` の詳細を、自分の作品に合う内容へ変更します。
6. 紹介内容が完成したら、その欄の `<span>紹介予定</span>` を削除します。Ctrl+Sで保存し、ブラウザーを再読み込みします。

| 欄 | 検索する文字 | 現在の仮画像 |
| --- | --- | --- |
| 受付・操作画面 | `id="entry"` | `demo-screen-placeholder.svg` |
| マッチング待機 | `id="waiting"` | `matching-wait-placeholder.svg` |
| マッチング成立 | `id="matched"` | `matching-result-placeholder.svg` |
| サーバーの処理・ログ | `id="logs"` | `server-log-placeholder.svg` |
| データの管理 | `id="data"` | `matching-data-placeholder.svg` |
| 実行環境・動作確認 | `id="environment"` | `matching-environment-placeholder.svg` |

### 2. 欄を増やす・減らす

各欄は `<article class="detail-row" ...>` から対応する `</article>` までが1組です。この1組をコピーすると追加できます。

追加した欄は `id` と `aria-labelledby`、見出しの `id` を重複しない名前に変更します。例えば `id="cancel"`、`aria-labelledby="cancel-title"`、見出しを `id="cancel-title"` にします。目次の `detail-index-items` 内に `<a href="#cancel"><span>07</span> キャンセル</a>` を追加すれば、その欄へ移動できます。削除する場合は article と対応する目次リンクの両方を削除します。

画像の大きさは `style.css` の `.detail-media img` の `height: 310px` で調整できます。横幅は `.detail-row` の `grid-template-columns` で決まります。説明を長くすると行の高さも増えるため、まずは各小見出しにつき2〜3文を目安に書いてください。

参考にした[個人制作ページ](https://sites.google.com/view/m07iewaki/個人制作)のように処理単位で紹介し、画像と説明を横に並べて縦の移動を抑えています。

## 12. おすすめの作業順

1. まず `index.html` を開き、ページ構成を確認する。
2. 氏名、所属、志望領域、紹介文を置き換える。
3. 代表作品1件の文章を、詳細ページまで書く。
4. 作品画像を差し替え、動作動画やソースコードへのリンクを付ける。
5. スキル、自己紹介、連絡先を整える。不要な項目は削除する。
6. 色や余白を少しずつ調整する。
7. PCでの表示とリンクを確認する。
8. GitHub Pages へ公開し、公開 URL でも確認する。
9. 制作が進んだら、作品や検証結果を更新する。
